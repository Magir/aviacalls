# AviaCalls

Записывает встречи в Zoom и делает транскрипт с именами говорящих. Запись и распознавание работают локально. По желанию можно подключить словарь и редактировать стенограмму через OpenRouter: исправлять имена, термины, пунктуацию и ошибки распознавания.

## Установка

Одна строка в Терминале (ставит в `/Applications` и запускает):

```bash
curl -fsSL https://raw.githubusercontent.com/Magir/aviacalls/main/install.sh | sh
```

Сборки не нотаризованы: приложение подписано ad-hoc, и macOS открывает его без вопросов только потому, что файлы, скачанные `curl`, не получают атрибут карантина. Архив, скачанный браузером, Gatekeeper заблокирует. Обновления приложение находит само: проверяет при запуске и раз в сутки, найденная версия появляется в меню пунктом «Доступно обновление … — скачать и установить». Архивы обновлений подписаны ключом Sparkle (EdDSA), Developer ID для этого не нужен. Релизы подписаны своим сертификатом “AviaCalls Signing” (самоподписанный, до 2036 года), поэтому выданные разрешения переживают обновления. Сертификат лежит в секретах репозитория `SIGN_CERT_P12` и `SIGN_CERT_PASSWORD`, см. `scripts/ci-keychain.sh`.

Нужен Mac на Apple Silicon и macOS 14.4+.

## Сборка из исходников

Нужен Xcode. Для сборки с разрешениями, которые переживут пересборку, импортируй в кейчейн сертификат “AviaCalls Signing” (см. scripts/bundle.sh); без него собирай `make app` с ad-hoc подписью.

```bash
scripts/bundle.sh          # сборка для своей машины, подпись AviaCalls Signing
open build/AviaCalls.app
make zip                   # архив для раздачи; в CI с SIGN="AviaCalls Signing"
```

Релиз: `git tag v0.2.0 && git push --tags` — GitHub Actions соберёт `AviaCalls.zip` и приложит к релизу, `install.sh` всегда берёт последний.

## Разрешения при первом запуске

- **Универсальный доступ** — читать список участников и состояние микрофонов в окне Zoom. При первом запуске появится системный запрос; позже нужный раздел настроек открывает пункт меню «Выдать доступ».
- **Микрофон** — запрос появится сам.
- **Запись системного звука** — запрос появится на первой встрече.
- **Запись экрана** — для снимков демонстраций. Во время показа экрана (твоего или чужого) приложение раз в 3 секунды смотрит на окно Zoom и сохраняет кадр в `screens/`, если картинка статична и отличается от прошлой. Снимки встают в расшифровку строками `(экран) screens/…jpg` и показываются в окне «Встречи». Разрешение запрашивается на первой записи; позже — пункт меню «Разрешить снимки демонстраций экрана…».
- **Уведомления** — всплывающие сообщения о начале и конце записи и об ошибках. Если запрос не появился или был отклонён, включи их пунктом меню «Включить уведомления о записи…».

Иконка в менюбаре показывает состояние: красный мигающий кружок — идёт запись, оранжевый треугольник — проблема (текст в меню), пузырь с текстом — идёт расшифровка.

Модель распознавания речи (Whisper large-v3-turbo, 1,5 ГБ) ставится отдельно: пункт меню «Скачать модель распознавания» или кнопка в окне «Встречи». Пока модели нет, встречи записываются и ждут; после установки расшифровываются сами. Модель лежит в `~/Library/Application Support/AviaCalls`.

## Как пользоваться

Приложение живёт в менюбаре. Пункт «Встречи…» открывает окно со списком встреч: дата, название, участники, расшифровка, кнопки «Открыть расшифровку», «Открыть запись» (оба голоса в одном файле `recording.m4a`) и «Скопировать путь к папке». Запись начинается сама, когда открывается окно встречи Zoom, и заканчивается после 10 секунд без него. Если за первую минуту в окне не нашлось ни участников, ни кнопки выхода (пустое окно до входа во встречу), запись удаляется и в список не попадает. Результат — в `~/Documents/Meetings/`.

Zoom не показывает участникам, что идёт запись. Предупреждай их сам.

## Постобработка стенограммы

Пункт меню «Настройки обработки текста…» позволяет подключить CSV с правильными именами, названиями и пояснениями. Словарь каждый пользователь подключает сам; корпоративный файл можно распространять отдельно от приложения и его исходников.

Формат — UTF-8, разделитель запятая, первая строка `term,description`. `term` — правильное написание, `description` — необязательное пояснение: должность человека, назначение продукта или контекст. Например, с вымышленными данными:

```csv
term,description
Орбита,Внутренний сервис планирования
Алёна Лисова,"Руководитель продукта, отвечает за Орбиту"
```

Запятые и переносы в пояснениях заключаются в двойные кавычки, кавычка внутри поля записывается как `""`. Поддерживаются UTF-8 BOM и окончания строк LF/CRLF. Термины должны быть непустыми, однострочными и уникальными без учёта регистра. Лимиты: 5000 терминов и 1 МиБ на файл. Приложение сохраняет копию в `~/Library/Application Support/AviaCalls/glossary.csv`; для обновления нужно подключить новый CSV. Исходный файл не меняется, «Отключить словарь» удаляет только копию приложения.

В том же окне сохрани свой API-ключ OpenRouter. Модель по умолчанию — `anthropic/claude-sonnet-5.5`, её можно заменить на любой ID из OpenRouter; пустое поле возвращает модель по умолчанию. Ключ хранится в Связке ключей macOS. Нужна модель с поддержкой JSON Schema, доступная у провайдера с Zero Data Retention; запросы требуют `provider.zdr=true` и запрещают сбор данных провайдером. Если подходящего провайдера нет, обработка завершится ошибкой. Политики и ограничения: [OpenRouter ZDR](https://openrouter.ai/docs/guides/features/zdr), [сбор данных OpenRouter](https://openrouter.ai/docs/guides/privacy/data-collection). ZDR регулирует хранение данных, но сама обработка происходит на внешних серверах.

При обработке **текст реплик и весь подключённый словарь передаются OpenRouter и провайдеру выбранной модели**. Аудио, снимки и заголовок встречи не отправляются; имена и другие сведения, произнесённые в разговоре, могут присутствовать в тексте. Запросы платные, оплачиваются со счёта пользователя OpenRouter. Содержимое запросов и ответов приложение не пишет в логи. В разработку и публичный репозиторий реальные словари, встречи и API-ключи добавлять не нужно.

По умолчанию модель исправляет пунктуацию, регистр, орфографию и очевидные ошибки распознавания, убирает бессмысленные заполнители и случайные повторы. Инструкция требует сохранить факты, числа, отрицания, сомнения, самоисправления и значимые повторы; не пересказывать и не дополнять встречу. Словарь помогает выбрать написание, его описания не добавляются в речь. Реплика, состоящая только из заполнителей, сохраняется, чтобы не оставлять пустую строку.

В разделе «Инструкция модели» можно изменить редакционные правила и сохранить их или восстановить инструкцию по умолчанию. Полный отправляемый системный промпт доступен для просмотра: приложение добавляет обязательные правила сохранности смысла и формата ответа. Словарь и фрагменты речи идут отдельными сообщениями. Инструкция хранится локально (`openRouterInstruction` в UserDefaults) и фиксируется на всю обработку встречи.

Автоматическая обработка по умолчанию выключена. Переключатель «Автоматически улучшать новые встречи» действует для записей, начатых после его включения: после локальной расшифровки они отправляются в OpenRouter. Если модель распознавания ещё не установлена, отметка сохраняется до появления локального транскрипта; на момент отправки функция тоже должна быть включена. Старые встречи автоматически не отправляются. Обработку любой готовой расшифровки можно запустить кнопкой «Улучшить текст…» в окне «Встречи» с подтверждением отправки.

Исходный `transcript.md` сохраняется. Результат записывается отдельно в `transcript.corrected.md`, в окне встречи появляются версии «Отредактированная» и «Исходная». Поиск использует актуальную обработанную версию. Если исходная расшифровка изменилась, старая обработанная копия перестаёт подменять её в окне и поиске. Повторная обработка всегда начинается с исходника и заменяет только обработанную копию.

Модель возвращает полный текст каждого фрагмента по его ID. Приложение проверяет полноту ответа, отсутствие лишних полей, повторяющихся ID, пустых строк и переносов, а также ограничивает объём результата. Длинные реплики делятся по пробелам на части до 4000 символов и 8000 байт UTF-8; порция содержит до 32 частей и 8000 байт речи. Пробелы между частями остаются в исходном документе. Слишком длинное слово без пробелов останавливает подготовку до первого платного запроса. Время, говорящие и ссылки на снимки не меняются. LLM всё равно может исказить смысл или неверно выбрать имя — важные фразы нужно сверять с исходником.

Весь словарь входит в каждый запрос. Его стабильный префикс сериализуется один раз на встречу; для Claude при нескольких порциях включается кэш на 5 минут, чтобы повторная обработка словаря могла стоить дешевле. Для одной порции явный кэш не запрашивается. Попадание в кэш зависит от модели и провайдера; первая запись кэша может стоить дороже обычного ввода. Требование ZDR сохраняется. Подробнее: [кэширование OpenRouter](https://openrouter.ai/docs/guides/best-practices/prompt-caching). Снижение стоимости проверяется по фактическим расходам, а не предполагается заранее.

Лимит CSV не гарантирует, что словарь размером 1 МиБ поместится в контекст выбранной модели. Ошибка 413, а иногда и 400 от OpenRouter, может означать переполненный контекст: сократи словарь либо выбери модель с большим контекстом. При ошибке или неполном ответе частичный результат не сохраняется, автоматических повторных запросов нет. Отключение автоматической обработки останавливает последующие запросы; уже отправленный запрос завершится, и если он был последним, результат сохранится — он уже оплачен.

Во время и после обработки рядом со встречей показан накопленный расход в USD из поля `usage.cost` ответа OpenRouter. Если хотя бы для одного запроса цена ещё не пришла или ответ оборвался, показано «не менее» известной суммы; если цены не пришли вовсе — «Стоимость недоступна». Запросы, которые не ушли с компьютера или которые OpenRouter отклонил до модели (ключ, баланс, лимит, нет подходящего провайдера), считаются бесплатными. Расход хранится в `postprocessing.json` в папке встречи. Отметка о незавершённом запросе сохраняется до отправки, поэтому закрытие приложения во время обработки не превращает неполную сумму в точную. У старых встреч истории расходов нет.

Новые расшифровки сохраняют точную разметку говорящих в `transcript.speakers.json`. В старых файлах без неё двоеточие в имени невозможно надёжно отличить от двоеточия в речи: в таких строках исправляется только текст после последнего `: `. Чтобы обработать всю реплику, можно сначала пересобрать локальный транскрипт командой `--transcribe <папка>`; при сохранённых `segments.json` повторное распознавание аудио не требуется.

## Команды для отладки

```bash
build/AviaCalls.app/Contents/MacOS/AviaCalls --dump-ax              # снимок окна встречи в JSON
build/AviaCalls.app/Contents/MacOS/AviaCalls --record-test 20       # записать 20 секунд во временную папку
build/AviaCalls.app/Contents/MacOS/AviaCalls --transcribe <папка>   # пересобрать транскрипт встречи
```

## Настройки

```bash
defaults write ru.magir.aviacalls micVoiceProcessing -bool NO   # эхоподавление микрофона: YES/NO принудительно; без настройки включается только на встроенных динамиках
defaults write ru.magir.aviacalls whisperModel <имя>            # другая модель из argmaxinc/whisperkit-coreml, без префикса openai_whisper-
defaults write ru.magir.aviacalls whisperLanguage ru                 # язык принудительно; без настройки определяется один раз на дорожку
defaults write ru.magir.aviacalls whisperChunking vad                # нарезка по паузам вместо сплошной расшифровки
defaults write ru.magir.aviacalls saveSnapshots -bool YES            # отладка: снимки окна Zoom в папку встречи раз в 30 секунд
defaults write ru.magir.aviacalls myName "Имя в Zoom"           # если приложение не узнало, кто из участников ты
defaults write ru.magir.aviacalls transcriptExportDir "~/path/to/Vault/00-Inbox"   # то же, что пункт меню «Копировать транскрипты в папку…»: копия каждого транскрипта с YAML-шапкой (например, в инбокс Obsidian); повторная расшифровка перезаписывает тот же файл
```
